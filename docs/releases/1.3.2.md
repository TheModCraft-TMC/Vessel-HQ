# Vessel HQ 1.3.2

Status: release preparation; not published. API and datastore compatibility
remain at Portainer `2.45.0`.

## Changes since 1.3.1

- Renew short-period Vault tokens before expiration and wake the renewal worker
  after source changes. Record the Git commit actually downloaded, validate
  source updates before persistence, clean failed downloads and honor preview
  and discovery cancellation.
- Reset activity pagination when filters change, export the complete filtered
  result, reject invalid offsets and decode base64 log payloads as UTF-8.
- Correct cgroup memory-cache accounting, aggregate block I/O across devices
  and format headerless registry manifest digests as `sha256:<hex>`.
- Generate typed Vault source update and connection-test contracts.
- Align shared console layouts, table spacing and fixed action bars. Contain
  mobile navigation focus and keep the drawer above fixed actions.
- Add the standalone Code Mode MCP adapter in `tools/vessel-mcp`. It requires
  explicit configuration and is not automatically enabled in Vessel.
- Carry forward Docker SDK/Compose compatibility and security repairs. Native
  extension support remains experimental; managed execution, production
  activation and rollback are future work.

## Security and validation

- Fix the fresh npm audit gate: pnpm 10 JSON mode returns status 1 for low
  findings even with `--audit-level=moderate`. Complete low-only reports now
  pass; moderate/high/critical findings and incomplete/failed scans still block.
  CLI regression tests verify both exit status and retained report contents.
- Update the redirect and glob-matching dependency graph for newly reported
  advisories. See the [release verification record](../security/release-readiness-1.3.2.md)
  for exact versions and compatibility checks.
- Retain the local deepmerge mitigation and visible low advisory. It has no
  upstream patched release; this is not an advisory-free dependency claim.
- The [Go dependency follow-up](../../backend-src/DEPENDENCY_SECURITY.md)
  remains tracked in #262. Current selected Docker monolith/Distribution
  advisory ranges have not been removed by this release preparation.

## Publication checklist

- Complete and review the [fresh release checks](../security/release-readiness-1.3.2.md),
  including remaining Go findings and authenticated UI coverage (#241).
- Commit release changes and obtain successful CI on that exact revision.
- Build the release context from the committed source. Execute-check both
  `linux/amd64` and `linux/arm64` images before publication.
- Publish immutable `1.3.2`, verify its platforms and digest in Docker Hub and
  GHCR, then promote `latest` to the same digest in both registries.
- Follow the [deployment and rollback guide](../themodcraft/release-and-deployment.md)
  and verify the runtime version before calling deployment complete.
