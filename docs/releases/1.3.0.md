# Vessel HQ 1.3.0

Vessel HQ 1.3.0 finalizes the frontend source migration and ships the refreshed
console with explicit domain/provider boundaries, updated tooling, and project
documentation. API and datastore compatibility remain at Portainer `2.45.0`.

## Highlights

- Consolidates frontend ownership in `web-src/core`, `domains`, `providers`,
  `shared`, and `ui`, removing the obsolete legacy source tree.
- Keeps Next.js App Router routes/layouts as application entry points and aligns
  Docker, Kubernetes, Azure, administration, and delivery views with their owners.
- Enforces public domain/provider APIs and route compliance with architecture
  checks; updates generated API paths and shared HTTP configuration.
- Updates console composition, navigation, search, and resource loading states.
- Enables React Compiler and Turbopack for local development; production builds
  continue using webpack and Next.js standalone output.
- Updates shared UI integrations, including Radix dropdown menus.
- Fixes container launcher exit-code preservation so successful backend commands
  such as `--version` remain successful when the frontend is shut down.
- Adds development-only LogRocket diagnostics with URL, header, input, and body
  sanitization. Production builds do not initialize this development integration.
- Rewrites the README with Vessel logos, a Docker overview screenshot, and
  migration/tooling badges; adds repository and frontend agent guidance.
- Records a future add-on/plugin architecture. Plugin support is not implemented.

The frontend migration was built using GPT-5.6 Sol agents exclusively, according
to the maintainer's attribution.

## Included foundation

This release retains the original 1.3.0 environment UI improvements: colocated
component styles, shared SortableList primitives, Vessel depth tokens, the
administrator Add environment action, and the unified local backend/frontend
development launcher.

Fork-specific GitOps, Vault, role/access-control, registry, activity-log, and
realtime features remain part of Vessel HQ. Their broader history is in the
[feature catalog](../recent-features/README.md).

## Replacement of the earlier 1.3.0 publication

At the maintainer's explicit request, the earlier 1.3.0 publication is preserved
as [1.3.0-beta.1](1.3.0-beta.1.md), and the stable GitHub release and Docker
`1.3.0` tag are replaced by this finalized build. This is a one-time exception to
the normal immutable-version policy. Future releases must use unused versions.

The archived image retains its original digest and embedded 1.3.0 version.
Existing installations must pull again to obtain the finalized image; a cached
image or an updater that compares only version numbers may not detect this
replacement. Recreate the container using the verified new image digest while
preserving the data volume and runtime configuration.

## Compatibility and images

- Vessel product/image version: `1.3.0`.
- Upstream API/datastore baseline: `2.45.0`.
- Development auto-login and diagnostics remain restricted to development mode.
- `themodcrafttmc/portainer:1.3.0` and `themodcrafttmc/portainer:latest` will
  reference the same verified multi-architecture image (AMD64 and ARM64).
- The old build remains available as `themodcrafttmc/portainer:1.3.0-beta.1`.
