# Vessel HQ 2.39.3.2.27-beta.1

Channel: beta. Publish as a GitHub prerelease and the Docker `beta` alias.

This release completes the frontend domain and provider refactor after the
`2.39.3.2.26` React migration checkpoint. Upstream API and database compatibility
remain at Portainer `2.45.0`. Images continue to use
`themodcrafttmc/portainer`; the registry migration remains a separate decision.

## Changes

- Organizes application startup, routing, product domains, infrastructure
  providers, and shared UI behind enforced module boundaries.
- Repairs authentication provider placement, post-hydration startup, and hard
  reload/logout transitions so public pages and authenticated layouts load
  correctly.
- Restores standard-user navigation and avoids administrator-only settings
  requests for those users.
- Validates OAuth callback state before creating a new login state, handles
  callbacks in both query strings and hash routes, and preserves authorization
  codes and settings containing reserved URL characters.
- Supports named lazy route exports that are already lazy under React 19.
- Stabilizes environment synchronization and explicitly maps Docker, Podman,
  Kubernetes, and Azure layout platforms.
- Consolidates global terminal and ingress styles and resolves scoped CSS
  ordering and Babel build warnings.
- Makes release CI use `RELEASE_VERSION`, reject version/tag mismatches, and
  prevent overwriting existing published tags. Validation runs before
  publication, and the immutable multi-architecture image is verified before
  its digest is promoted to the matching channel alias (`beta` for this release).
- Displays the full beta version in the UI, keeps beta tags out of stable
  update discovery, and permits upgrading a beta to its corresponding stable
  release.
- Generates SHA-256 checksums for both release binaries.

The numeric candidate runtime images reported `ServerVersion=2.39.3.2.27` and
`DatabaseVersion=2.45.0`. The final beta must report `ServerVersion=2.39.3.2.27-beta.1`;
its publication verification is recorded on the GitHub prerelease. The release context is in `dist/release-context/`.
The temporary smoke containers were removed after validation.

The production bundle has two non-blocking size warnings: the largest vendor
asset is 3.44 MiB against a 3 MiB budget, and the main entrypoint is 7.71 MiB
against a 6 MiB budget. These warnings remain visible. Node 22 also emits a
transitive `punycode` deprecation warning during frontend tests.

Live Kubernetes resource routes require a Kubernetes environment for browser
smoke testing. The previously recorded Docker browser and OAuth checks are in
the [frontend verification snapshot](../planning/frontend-refactor-progress-2026-09-23.md).

## Publication

Commit the verified source, build the final beta context, then push `v2.39.3.2.27-beta.1` to run the
release workflow or dispatch it manually from that commit. Local publishing
commands are generated in `dist/release-context/BUILD-IMAGE.txt` by
`scripts/build-release-context.sh`; regenerate that context after committing.
Keep the immutable tag and `beta` on the same verified OCI index digest.

Deployment and rollback remain documented in the
[release and deployment guide](../themodcraft/release-and-deployment.md).
