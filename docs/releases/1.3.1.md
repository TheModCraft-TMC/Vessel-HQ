# Vessel HQ 1.3.1

Vessel HQ 1.3.1 repairs the release build after a grouped dependency update and
restores component styles that the Next.js migration had silently dropped. API
and datastore compatibility remain at Portainer `2.45.0`.

## Fixed

- Switch controls and stack webhook URLs work with `uuid` 14, which removed the
  default export and the `uuid/v4` entry point. Switch IDs now use React
  `useId`.
- Bootstrap stays on 3.4.1 instead of 5.x. The console only loads Bootstrap CSS
  and its markup uses Bootstrap 3 classes.
- `yaml` stays on the patched 1.x line (1.10.3), and Vitest stays on the patched
  4.x line (4.1.12), so coverage tooling keeps matching peer versions.
- 48 class reads in 21 components used camelCase names (`styles.copyButton`)
  for kebab-case classes (`.copy-button`) and resolved to nothing after the
  Next.js migration. Visible effects included the copy button's "copied" tick
  always showing, and missing sort-icon, wizard, tag, tooltip, JSON tree, and
  status styles. The classes are now camelCase.
- `pnpm lint:ci` runs a new CSS Module class check so a missing class name fails
  CI instead of rendering unstyled.

## Dependency security scope

<!-- REVIEW: The Bootstrap compatibility pin reopens scanner findings, even
though their JavaScript attack paths are absent from the CSS-only console. -->
Bootstrap 3.4.1 is end-of-life and has known JavaScript tooltip/popover XSS
advisories ([GHSA-vxmc-5x29-h64v](https://github.com/advisories/GHSA-vxmc-5x29-h64v)
and [GHSA-q58r-hwc8-rm9j](https://github.com/advisories/GHSA-q58r-hwc8-rm9j)).
The console imports only its stylesheet, not those JavaScript plugins. This
compatibility pin does not address the repository's other dependency advisories;
do not add Bootstrap JavaScript without reassessing these findings.
