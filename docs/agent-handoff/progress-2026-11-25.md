## Extension safety and periodic refresh correction — active continuation

- Periodic server refreshes now use a distinct `snapshot` event. The client
  refreshes environment health lists and scoped provider resources rather than
  session/settings/version/extension queries. Docker/Podman resources with an
  active engine watch use real events; Kubernetes/ACI retain scoped fallback
  refresh. Actual mutation events and ready barriers still resynchronize.
- Native preview and stack drawers verify on entry, retain an unchanged verified
  snapshot during background revalidation, and stop on errors or revoked grants.
  Regression coverage preserves an unsaved editor and an open drawer.
- Host SDK guard stops request bursts (>120/minute), repeated non-cancellation
  failures (>8/30 seconds), repeated mounts of the same view (>6/minute), and
  render/bundle failures. It cancels live traffic streams, blocks further SDK
  calls and sends one safety report. A session-storage marker prevents reload
  escape; an explicitly new approval timestamp gets a fresh guard.
- New admin-only safety-trip endpoint binds revision, package digest and approval
  timestamp. It revokes UI/service grants and image automation, preserves notes
  and settings, writes a fixed-reason audit action and broadcasts once. Old-tab
  reports cannot revoke a newly reviewed approval. Configuration shows the reason.
- Server SDK fallback limits per-user/extension requests, auto-disabling on an
  administrator's excess. Restricted users receive 429 without being able to
  revoke another user's extension. Capacity exhaustion cannot disable an
  innocent extension. Traffic streams are capped at four per user/extension,
  with bounded bookkeeping and capacity released on close.
- Registry/slot verification and safety reporting have bounded HTTP deadlines.
  Native UI remains trusted browser-context code: these SDK guards are not a
  sandbox or a way to stop arbitrary synchronous JavaScript or raw browser APIs.
- Builder cache ownership is now confined to the three writable tool cache
  directories owned by `node`, preserving non-root builds without world-write.
