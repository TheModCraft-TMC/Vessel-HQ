# i18next advisory remediation — November 25, 2026

The fresh CI npm audit found the same moderate advisory in two locked versions:
the application runtime and the translation extractor's dependency. This review
checked those exact versions, the selected patched version, the extractor's
registry metadata and their Babel-runtime dependency. It is not an independent
audit of every package in the application. The CI gate scans the complete lockfile,
including build tooling.

| Package | Known vulnerability | Action | Audit detail |
| --- | --- | --- | --- |
| i18next 21.10.0 / 23.16.8 | GHSA-6jcc-5g8w-32mx / CVE-2026-63402, moderate; inherited-object recursion can corrupt shared built-ins and cause denial of service | Upgrade both paths to verified patched 26.3.4 | [Package assessment](https://npmscan.com/package/i18next), [advisory](https://npmscan.com/vulnerability/GHSA-6jcc-5g8w-32mx) |

The direct dependency and override pin `26.3.4`, covering the extractor's otherwise
vulnerable dependency range as well. The extractor moves from 0.9.2 to 1.1.0;
runtime plural/interpolation and actual Babel extraction regressions verify the
compatibility path. The advisory threshold is unchanged and no exception was added.

Separate supply-chain signals: registry metadata confirms both selected versions
exist and reports no known vulnerability in i18next 26.3.4 or the extractor itself.
Both packages use MIT licenses. No new install/postinstall hook is introduced;
i18next's maintainer `prepare` command is publish/development metadata. The
[extractor](https://npmscan.com/package/babel-plugin-i18next-extract) is aging
(last release over a year ago), not marked deprecated, and remains a build-time
dependency. That maintenance signal is separate from the fixed advisory.

Fresh full-lockfile audit results and compatibility-test receipts are recorded
in the [current handoff](../agent-handoff/progress-2026-11-25.md). Only completed
receipts establish the final gate result.
